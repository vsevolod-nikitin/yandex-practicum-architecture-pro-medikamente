# Задание 3. Оценка Data Encryption at Rest and In Transit

## 1. Категории данных и уровень риска

В системе обрабатываются данные с разной степенью чувствительности. Для каждой категории определён соответствующий профиль риска.

| Категория | Примеры | Чувствительность | Уровень риска |
| --- | --- | --- | --- |
| Public | Маркетинговые материалы | Низкая | Низкий |
| Internal | Внутренние служебные сведения | Средняя | Средний |
| Personal Data (PII) | ФИО, телефон, адрес электронной почты | Высокая | Высокий |
| Medical Data | Диагнозы, результаты анализов | Критическая | Критический |
| Financial Data | Платежи и транзакции | Высокая | Высокий |
| Authentication Data | Пароли и токены | Критическая | Критический |

## 2. Защита отдельных типов данных

Выбор мер защиты зависит от возможных последствий раскрытия или неправомерного использования информации.

| Тип данных | Причина защиты | Рекомендуемые меры |
| --- | --- | --- |
| ФИО пациента | Относятся к персональным данным в соответствии с 152-ФЗ | Шифрование AES-256 в базе данных |
| Номер телефона пациента | Снижение риска раскрытия контактных данных | AES-256 и маскирование |
| Адрес электронной почты пациента | Предотвращение использования адреса для фишинга | AES-256 |
| Паспортные сведения | Защита данных, позволяющих установить личность | AES-256 и ограничение доступа |
| Медицинские карты | Соблюдение конфиденциальности медицинской информации | AES-256, RBAC и аудит действий |
| Результаты анализов | Защита конфиденциальных медицинских сведений | AES-256 и Data Tagging |
| Платёжные сведения | Снижение финансовых рисков | Токенизация |
| Пароли пользователей | Предотвращение раскрытия учётных данных | bcrypt или Argon2 |
| JWT-токены | Снижение риска перехвата пользовательской сессии | Короткий срок действия и TLS |
| Системные журналы | В логах могут присутствовать персональные данные | Маскирование и ограниченный доступ |

## 3. Автоматизированный контроль и управление данными

Для наблюдения за доступом к информации, выявления подозрительной активности и снижения риска утечек применяются следующие механизмы.

### Аудит действий

Журнал аудита должен фиксировать ключевые операции с данными:

- просмотр медицинских карт;
- изменение сведений;
- экспорт или выгрузку данных.

Для сбора и анализа журналов используется **ELK Stack**.

### SIEM и выявление аномалий

SIEM помогает обнаруживать действия, которые могут указывать на нарушение безопасности. Например:

- массовые обращения к картам пациентов;
- доступ к системе в нерабочее время;
- нетипичные запросы к API.

В качестве инструмента SIEM применяется **Wazuh**.

### Предотвращение утечек данных (DLP)

DLP-контроль помогает отслеживать возможные каналы передачи конфиденциальных сведений, в том числе электронную почту, выгрузки и копирование файлов.

### Управление данными (Data Governance)

Для системного управления конфиденциальной информацией используются классификация данных, контроль доступа и правила хранения.

#### Маркировка данных (Data Tagging)

Для обозначения категорий информации можно применять теги:

- `PII`;
- `MEDICAL`;
- `FINANCIAL`;
- `CONFIDENTIAL`.

#### Управление доступом (Access Control)

Для разграничения прав пользователей предусмотрены модели **RBAC** и **ABAC**.

#### Сроки хранения (Data Retention)

Срок хранения определяется типом данных:

| Категория данных | Срок хранения |
| --- | --- |
| Медицинские сведения | 5–10 лет |
| Журналы событий | 1 год |
| Временные данные | 30 дней |

## 4. Реестр средств защиты

Ниже перечислены программные и инфраструктурные средства, используемые для защиты системы и информации.

| Область | Средство | Назначение |
| --- | --- | --- |
| IAM | Keycloak | Аутентификация пользователей и управление правами |
| Безопасность API | API Gateway | Контроль и защита API |
| Шифрование канала | TLS 1.3 | Защита данных при передаче |
| Шифрование базы данных | PostgreSQL Encryption | Защита данных в базе |
| Управление секретами | HashiCorp Vault | Безопасное хранение секретов |
| Мониторинг и журналы | ELK Stack | Сбор и анализ событий системы |
| SIEM | Wazuh | Выявление и анализ событий безопасности |
| Безопасность контейнеров | Kubernetes Secrets | Хранение секретов и ключей |
| Защита резервных копий | Зашифрованные резервные копии | Защита резервных данных |
| Маркировка данных | Apache Atlas | Классификация и разметка данных |
